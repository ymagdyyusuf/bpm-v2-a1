# الاختبار الذاتي — محسوب، بلا مبالغة

> **المبدأ الحاكم:**
> **اختبر اللي بيفشل بصمت. سيب اللي بيفشل بصوت عالي.**
>
> زرار شكله غلط هتشوفه أول ما تفتح الشاشة. حساب حالة غلط في حالة نادرة — عمرك ما هتشوفه،
> هتكتشفه بعد شهور في تقرير بيقول رقم مش صح. **الاختبار للنوع التاني.**

---

## القاعدة الوحيدة للتغطية

**مفيش نسبة تغطية مستهدَفة.** النِسَب بتخلّي الناس تكتب اختبارات فاضية.

> **المقياس: كل قاعدة عمل مكتوبة في `UNDERSTANDING.md` لها اختبار واحد على الأقل.**
> **ولا حاجة تانية مطلوبة.**

قاعدة عمل بلا اختبار = القاعدة موجودة في راسك بس، مش في النظام.

---

## المستويات الخمسة

### ١. اختبار المرحلة — بوابة واحدة لكل مرحلة

| المرحلة | الاختبار — نفّذه فعلاً، ما تفترضش |
|---|---|
| ٠ التأسيس | اطلب كتابة `notes.md` → لازم **يترفض** بذكر R-6 |
| ١ الفهم | يوسف قرأ الصفحة وقال "ده صح" |
| ٢ التحليل | **صفر** بنود `[استنتاج]` غير مراجَعة |
| ٣ الشاشات | كل حقل في جدول التدفق له **كاتب واحد** — عدّهم |
| ٤ البيانات | المخطط يستوعب **حالة حقيقية واحدة كاملة** من شغل يوسف، من الأول للآخر |
| ٥ التصميم | الشاشة اتشافت بـ**نص عربي حقيقي طويل** — مش نص وهمي |
| ٦ البناء | لكل شريحة إثباتها (تحت) |
| ٧ الملحق | كل مفصل في `APPENDIX.md` لسه مفتوح |

### ٢. اختبار المنطق — الأساس

**القاعدة:** دالة في `src/lib/` فيها **شرط أو حساب أو تصنيف** → **لها اختبار**.
دالة بتنقل بيانات من شكل لشكل بلا قرار → **لأ**.

لكل قاعدة عمل، **ثلاث حالات بس**:
```
الحالة العادية   → النتيجة المتوقعة
حالة الحد        → القيمة عند الخط الفاصل بالظبط
حالة الفراغ      → لا بيانات / null
```

تلاتة. مش عشرة.

### ٣. اختبار الشاشة — ثلاث حالات، لا رابع

كل شاشة تتفتح في المتصفح وتتشاف بعينك في:

```
١. بيانات حقيقية    → بتعرض صح
٢. فاضية            → رسالة مفهومة، مش شاشة بيضا ولا خطأ
٣. نص عربي طويل     → التخطيط ما اتكسرش
```

**الحالة ٣ مش رفاهية.** العربي بيطوّل النص وبيغيّر اتجاه التخطيط — الشاشة اللي شكلها تمام بالإنجليزي بتتكسر بالعربي.

**مش مطلوب:** اختبار كل زرار، ولا كل مسار، ولا لقطات مقارنة.

### ٤. اختبار الشريحة — الإثبات

كل شريحة ليها **جملة إثبات واحدة** تتكتب **قبل البناء**:

```
الإثبات: "أقدر أفتح <الرابط>، أعمل <الفعل>، وأشوف <النتيجة> محفوظة بعد إعادة التحميل."
```

الشريحة ما تخلصش غير لما الجملة دي تتنفّذ **فعلياً على الرابط الحي** — مش محلياً، ومش "المفروض تشتغل".

**"إعادة التحميل"** جزء أساسي: هي اللي بتفرّق بين حاجة اتحفظت فعلاً وحاجة عايشة في الذاكرة.

### ٥. اختبار ما قبل النشر

```
npx tsc --noEmit     ← الأنواع
npm run build        ← البناء
npm test             ← اختبارات المنطق
```
**+ جملة الإثبات اتنفّذت على الرابط الحي.**

أي واحد فشل = ممنوع النشر.

## اللي ما يتختبرش — صراحةً

عشان ما ننجرفش:

| ما نختبرش | ليه |
|---|---|
| الألوان والمسافات والخطوط | بتبان بالعين فوراً |
| سلوك المكتبات (Next.js, React, المتصفح) | مش شغلنا، ومتختبَرة عندهم |
| دوال بتنقل بيانات بلا قرار | مفيش فيها حاجة تغلط |
| كل مسارات النقر | تكلفة عالية، عائد منخفض لنظام داخلي |
| حاجة لسه بتتصمّم | الاختبار بيتجمّد على تصميم هيتغيّر |
| شاشة إعدادات داخلية محدش هيشوفها غير يوسف | الفحص بالعين أرخص |

**قاعدة الحسم عند الشك:**
> *"لو ده غلط، هيبان إمتى؟"*
> **فوراً** → ما تختبرهوش. **بعد شهور في تقرير** → اختبره.

## الأدوات

| ليه | إيه |
|---|---|
| اختبار المنطق | `vitest` — سريع وإعداده سطرين |
| اختبار الشاشة | المتصفح بعينك (الثلاث حالات) |
| فحص الأنواع والبناء | `tsc` و`build` — موجودين أصلاً |

**مش مطلوب:** إطار اختبار واجهة، ولا لقطات مقارنة، ولا CI معقّد — لنظام بمستخدم واحد دي تكلفة بلا عائد.
لما عدد المستخدمين يزيد فعلاً، نراجع القرار ده بقرار جديد.

## الانضباط

- **`/verify`** بتشغّل المستويات ١ و٢ و٥ آلياً.
- **`@reviewer`** بيفحص: قاعدة عمل موثّقة بلا اختبار → `[مهم]`.
- **`/slice`** فيها خطوة الإثبات، وما بتقفلش من غيرها.
- الاختبار يتكتب **مع** الكود في نفس الشريحة. **ممنوع تأجيله** — المؤجَّل ما بيتكتبش.
