# معيار الكود — من صفة لقاعدة قابلة للفحص

> "كود نظيف" كلمة ما تلزمش حد. كل صفة هنا اتحوّلت لقاعدة يقدر المدقّق يفحصها ويقول مخالفة ولا لأ.

---

## ١. مرتّب — المكان بيقول الوظيفة

```
src/app/         شاشات — تعرض بس
src/components/  عناصر واجهة مشتركة
src/lib/         منطق الأعمال — لا JSX، لا استدعاء واجهة
src/lib/db/      الوصول لقاعدة البيانات
migrations/      تغييرات المخطط، مرقّمة
docs/draft/      مسودات مؤقتة
```

**القاعدة:** تعرف الملف بيعمل إيه من مساره قبل ما تفتحه.
**الفحص:** فيه منطق أعمال بره `src/lib/`؟ مخالفة.

---

## ٢. نقي — مسؤولية واحدة لكل ملف

**القاعدة:** الملف يتلخّص في جملة واحدة بلا "و".

```
"بيحسب حالة الطلب"                    ← نقي
"بيحسب حالة الطلب وبيبعت إشعار"        ← اتنين، يتفصلوا
```

**الفحص:** الملف عدّى ٣٠٠ سطر؟ غالباً بيعمل أكتر من حاجة. افحصه.

---

## ٣. سليم — كل قاعدة عمل ليها مصدر

**أخطر بند في المعيار كله.**

```ts
// ✗ منطق مخترَع — منين جت الـ٣٠؟
if (daysSince > 30) markStale(order);

// ✓ منطق موثّق
// [قاله يوسف]: الطلب يبقى متأخر بعد ٣٠ يوم من آخر حركة
if (daysSince > STALE_AFTER_DAYS) markStale(order);
```

**القاعدة:** أي شرط أو رقم أو تصنيف يخص المجال، فوقه تعليق بمصدره — `D-xx` أو `[قاله يوسف]`.
**منطق بلا مصدر = اختراع، حتى لو شكله منطقي.**

**الفحص:** `tsc --noEmit` و`build` ينجحوا. مفيش `any`.

---

## ٤. ديناميكي — اللي ممكن يزيد، يعيش في البيانات

**السؤال الفاصل:** *"لو يوسف عايز يضيف واحد كمان بكرة، هيحتاج مبرمج؟"*
لو الإجابة أيوه — يبقى في المكان الغلط.

```ts
// ✗ مثبّت في الكود — أي إضافة = تعديل كود + نشر
type Category = "عاجل" | "عادي" | "مؤجل";

// ✓ في قاعدة البيانات — يوسف بيضيف بنفسه
// جدول categories: id, name, sort_order, active
const categories = await fetchCategories();
```

**اللي يفضل في الكود:** الحاجات اللي تغييرها بيغيّر **سلوك** النظام (خطوات مسار مثلاً).
**اللي يروح جدول:** أي قايمة تسميات، تصنيفات، جهات، أنواع.

**الفحص:** فيه قايمة قيم مجال مثبّتة في الكود؟ اسأل يوسف: "ممكن تحتاج تزوّد واحدة؟" لو أيوه — جدول.

---

## ٥. قابل للتعديل — الربط بالمعرّف، مش بالاسم

```ts
// ✗ تغيير الاسم بيكسر الربط
if (item.category === "عاجل") { ... }

// ✓ الاسم للعرض بس، الربط بالمعرّف
if (item.categoryId === urgentId) { ... }
```

**القاعدة:** الاسم للعرض. الربط بالمعرّف الثابت. **يوسف يقدر يعيد تسمية أي حاجة من غير ما حاجة تتكسر.**

**والعكس:** ممنوع تخزّن حاجة محسوبة تقدر تشتقّها وقت العرض — لأنها بتتجمّد على قيمة قديمة لما الأصل يتغيّر.

---

## ٦. قابل للإضافة — المفصل قبل الإضافة

كل بند في `APPENDIX.md` بيفرض **مفصل** في المعمارية دلوقتي، بلا بناء دلوقتي.

```ts
// ✗ مقفول — إضافة دور تاني = إعادة كتابة
const canEdit = user.isManager;

// ✓ مفتوح — الدور الجديد بيتضاف كبيانات
const canEdit = hasPermission(user, "edit");
```

**القاعدة:** المفصل = **نقطة الامتداد موجودة**، **التنفيذ لأ**.
**الفحص:** بند `A-xx` في `APPENDIX.md` بقى أصعب بعد الشريحة دي؟ مخالفة — بلّغ.

---

## ٧. قابل للاندماج — حدود واضحة

**القاعدة:** كل ميزة تقدر تتشال أو تتبدّل من غير ما تكسر غيرها.

- الميزة تتكلم مع غيرها عبر **دوال معرّفة**، مش بالوصول لتفاصيلها الداخلية.
- ممنوع ملف "مساعدات عامة" فيه كل حاجة — ده بيربط كل حاجة بكل حاجة.
- منطق اتكرر في مكانين → ينتقل لـ`src/lib/` **فوراً**، مش "بعدين".

**الفحص:** عايز تشيل ميزة — كام ملف تاني هيتكسر؟ أكتر من حدودها؟ الحدود مش واضحة.

---

## ٨. قاعدة البيانات

1. كل تغيير في المخطط = **ملف مهاجرة جديد**. ممنوع تعديل ملف اتطبّق قبل كده.
2. `ADD COLUMN IF NOT EXISTS` دايماً — إعادة التشغيل ما تكسرش.
3. **"اتطبّقت" = ظاهرة في قائمة المهاجرات.** كتابة الملف ≠ تطبيق.
4. **يوسف هو اللي يشغّل المهاجرة على القاعدة الحية.** إنت تجهّزها.

---

## ٩. قبل أي commit

```bash
npx tsc --noEmit && npm run build
```

فشل واحد فيهم = ممنوع commit. مفيش استثناء، ولا حتى تحت ضغط وقت.
