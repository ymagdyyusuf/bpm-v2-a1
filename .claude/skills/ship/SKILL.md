# إقفال ونشر

## ١ — الاختبار الذاتي (ممنوع تخطّيها)

```
/verify
```

لازم كل سطر يرجع "نجح" — الأنواع، البناء، المنطق، تغطية القواعد، **والإثبات**.

أي سطر مش "نجح" = **قف**. أصلح، وشغّل `/verify` من أول وجديد.
**ممنوع commit فوق كود مكسور أو قاعدة عمل بلا اختبار — ولو يوسف مستعجل.**

## ٢ — بصّ على اللي هيتحفظ

```
git status --short
git diff --stat
```

- ملفات ما لهاش علاقة بالشريحة؟ **ما تحفظهاش.**
- ملف فيه مفاتيح أو أسرار (`.env*`)؟ **ممنوع منعاً باتاً** — بلّغ يوسف فوراً.

## ٣ — commit

ملفات بالاسم — **مش** `git add -A`:

```
git add <الملفات بالاسم>
git commit -m "<الشريحة في جملة>"
```

الرسالة تقول **ليه**، مش قايمة ملفات — الملفات بتبان في الـdiff.

## ٤ — push = نشر

```
git push
```

النشر تلقائي من الفرع الرئيسي. **ممنوع نشر يدوي** — الـhook هيمنعك، وده مقصود: الأمر اليدوي بيتنسي.

## ٥ — اتأكد إنه نزل

- افتح الرابط الحي من `CLAUDE.md`.
- **شوف التغيير بعينك.** "الـpush نجح" ≠ "التغيير ظاهر".
- الـbuild فشل عند مزوّد النشر؟ ده عطل مش تفصيلة — بلّغ فوراً.

## ٦ — قول ليوسف

سطرين: اتنشر إيه وعلى أنهي رابط · مطلوب منه إيه.

**فيه migration جديدة؟** قول صراحة: **"الكود اتنشر، بس قاعدة البيانات لسه ما اتغيّرتش."**
ده نوع الالتباس اللي بيكلّف ساعات.
